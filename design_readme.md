Before we start designing in Figma or writing any code, we need to do research first.

### 1 - Understand the Business

The first step before designing anything is to understand the business itself. To do that, we need to clearly define:

* The **business goals** — What does the company want?
* The **user goals** — What does the user want?

> Good design happens when business goals and user goals align.

#### Find the Business Goals (What does the company want?)

First, you need to understand the business and define clear objectives. These objectives are known as the **business
goals**.

Examples of business goals include:

* Generate leads - Sell products - Build trust - Increase subscriptions - Book appointments - Educate users - Grow a
  community

#### Find the User Goals (What does the user want?)

User goals represent what users are trying to achieve when they visit the website or application.

Examples of user goals include:

* Find information quickly - Compare pricing - Purchase safely - Save time - Feel confident in their decisions

### 2 - Research Phase

I like to do research first, specifically (Competitor Research) to find what already work in the industry i'm
design the website for and what the user already expects.

and area i Study includes:

* **layout patterns - navigation - typography - colors - CTAs - spacing - user flows**

> Note: you are not copying, you are studying what works to innovate

For Example, A banking app should feel **stable, clean and trustworthy**.

But A gaming site can feel **energetic, bold and animated**.

Different industries require different visual psychology.

### 3 — Information Architecture (Crucial)

Before design, we need to organize the content, this means:

* what pages exist, what sections exist, what order information appears.

For example, and ecommerce homepage will follow this flow:

* Hero
* Social proof
* Featured products
* Benefits
* Testimonials
* FAQ
* CTA
* Footer

This is called, **Information Hierarchy** which allows The user to naturally understand:

* what matters most, where to look next, what action to take.

### 4 - Wire framing

This is my favorite part, and it consists of creating a Low-fidelity structure with No colors and No fancy UI, Just the
layout. The purpose of this step is to focus on UX before visuals. I often spend MORE time here than on colors.

you can create, for Example:

* navbar, hero, cards, sidebar, buttons

### 5 - Design System (This Changes Everything)

This is also on of my favorit part as i translate directly into how your code is goit to be structure like.

A design system allows you to define:

* reusable rules, reusable components, reusable spacing, reusable typography, reusable colors,

Without a design system, everything becomes inconsistent and your frontend code lacks coherence.

Core Parts of a Design System include:

#### Typography

Consistency here matters more than creativity.

Usually:

* 1–2 fonts only
* clear heading scale
* consistent line heights

Example scale:

* H1 → 48px
* H2 → 36px
* H3 → 28px
* Body → 16px

#### Spacing System

PLEASE Do NOT randomly use 17px, 23px, 11px instead use a **spacing scale**.

Example:

* 4
* 8
* 12
* 16
* 24
* 32
* 48
* 64

This is Usually based on an 8px grid system which creates visual rhythm.

#### Color System

You don’t randomly pick colors.

You define:

* primary
* secondary
* accent
* neutral
* success
* warning
* error

Example:

* Primary = blue
* Accent = orange
* Background = neutral gray
* Text = dark gray

Good design uses:

* limited palettes
* strong contrast
* accessible colors

### 6 - Visual Hierarchy

This is one of the MOST important concepts.

Users should instantly know:

* what is important
* what is clickable
* what is secondary

You control hierarchy with:

* size
* weight
* spacing
* contrast
* positioning
* color

Example: <br/>
A giant bold headline attracts attention first. A Small gray text becomes secondary.

### 7 - UX Principles (Critical)

A beautiful UI with bad UX is a failure.

Learn:

* usability
* accessibility
* clarity
* responsiveness
* interaction feedback

#### Important UX Rules

Don’t Make Users Think, all Users should instantly understand:

* where they are
* what to do
* how to navigate

#### Consistency

* Buttons should behave the same everywhere.
* Forms should behave consistently.
* Spacing should feel predictable.

**Accessibility**

Accessibility is part of professional engineering, Professional products care about:

* keyboard navigation
* screen readers
* contrast ratios
* readable font sizes

### 8 - Prototyping

Now you create interactions.

Examples:

* hover states
* animations
* transitions
* page flows
* modal behavior

This helps:

* client approval
* user testing
* developer handoff

Usually done in:

* Figma
* Framer

### 9 - Responsive Design

This is Not an afterthought; I think mobile-first or responsive-first.
I Design for:

* desktop
* tablet
* mobile

### 10 - Build the Frontend

NOW I code. And I build mobile-first or responsive-first.

Good frontend engineers:

* preserve spacing
* preserve hierarchy
* preserve accessibility
* preserve responsiveness
* preserve interaction quality

I repeat this process every time I design and build a new view. It helps me translate design systems into scalable and
maintainable UI architecture.
